# V4/V5 发布与复现审查

审查日期：2026-11-11。本记录是发布前实现、依赖、冻结链和文档的独立审查，不是新的实验结果，也不是修改已冻结协议。审查期间没有改动 V4/V5 冻结的经济环境、训练或分析源码。没有声称已在另一台机器重新完成全部训练；结论来自依赖闭包、实际自检、文件哈希、Git 属性与复现入口检查。

## 环境与依赖

- 本地核验环境为 Python 3.11.5、NumPy 2.4.4、PyTorch 2.5.1+cpu，Windows。建议的 Python 3.11 与 NumPy 包元数据的 `Requires-Python >=3.11` 一致。
- 递归检查 V4/V5 环境、奖励审计、训练、分析、全共享回放及入口所需的 14 个 Python 文件，第三方导入只有 `numpy` 与 `torch`。[requirements.txt](../requirements.txt) 已覆盖；PyTorch 的常规传递依赖由 pip 解析安装。
- 整个奖励实验不需要绘图库。图形依赖仅供历史绘图命令使用。
- 当前策略在 CPU 上执行。README 给出 CPU wheel 的可选安装命令；不需要 GPU。
- 新代码以文件位置确定仓库根目录，没有依赖本地盘符或外部论文文件才能运行的步骤。

## 全新副本的执行链

在仓库根目录安装核心依赖后，可以执行：

```bash
python scripts/run_v4_incentives.py check
python scripts/run_v4_incentives.py all --workers 4
python scripts/run_v5_incentives.py check
python scripts/run_v5_incentives.py all --workers 4
```

`check` 不创建正式测试或选择检查点；V4 的经济检查可能创建可重算的缓存。`all` 包含阶段审计、完整验证候选、10 种子训练、测试前冻结、独立测试和分析。V5 的 `check` 还检查全共享回放，`test/all` 最后执行冻结策略的全共享回放。

发布负责人在最终入口整合后实际运行了上述两个 `check` 命令，均以退出码 0 完成；经济环境、平台 runner、阶段压力审计、统计分析及 V5 全共享回放的自检全部通过。这里记录的是最终入口的运行证据，不等同于在全新机器重复训练后的结果。

也可以分阶段使用 `train`、`test`。这种使用方式若要生成完整发布证据，还需要分别运行 `python code/incentive_stress.py all` 或 `python code/conditional_incentive_stress.py all` 完成独立阶段审计。已执行过 `all` 的阶段审计或正式测试会拒绝覆盖；重复完整研究应使用新的仓库副本。训练需要的检查点在本次运行中生成，不依赖仓库之外的旧权重。

V4/V5 输出在各自的 `experiments/` 子目录。测试轨迹、权重与运行日志不作为 Git 中的预置输入。公开参考统计与本地原始输出的作用不同：重新运行会生成新的冻结记录和输出哈希，不要求时间戳、压缩文件元数据或不同硬件浮点结果逐字节复刻旧运行。

## 冻结与换行稳定性

审查时，V4 主冻结清单中的 31 个文件和 V5 主冻结清单中的 34 个文件均与其原始 SHA256 匹配。两个设计冻结文件内部记录的 Markdown 哈希也全部匹配。新 Python 和 Markdown 源文件使用 LF，仓库默认 `.gitattributes` 保持 LF。

## 经济规则与公开信息

README 和协议准确说明：锁定的是本项目所选的 `A0`，即 `rho=0`、最大总容量匹配及均匀破同分；数值收费采用 `p=1, alpha=.2`，原始获配者付 `0.2*c+.8*b`。2024 论文给出一般分配函数，没有唯一规定本项目的匹配算法和全部数值参数，因此本项目没有声称完整恢复论文的唯一实现。

V5 新增的是领奖资格，不是资源资格、分配优先级或基础账单。条件只读取本人原始公开申报和可核验完成结果，不能读取真实需求来判断“诚实”。交易后的 VM 归属不改变原始账单；满足公开资格者经交换后完成，仍可获得已承诺奖励。

部署策略只读取报告、原始分配、原支付、完成标记、已付奖金和自己的承诺、预算、时间历史。V5 特征维度 71，40 个奖励动作的资格计算经过独立枚举；非零 Q 状态下的一次采样、一次更新验证通过。原始市场参数、Q 值、联盟标签、交换和转账只用于模拟器与离线审计。

## 强联盟回放及统计

[全共享回放](../code/evaluate_fullpool_incentives.py) 允许跨不同申报共享已租资源，联盟是外生压力场景，输出不将其解释为联盟形成率。真实需求只供环境判断任务完成和离线评价，不能进入平台 actor。

- 保留 V5 最坏 10 轮承诺预算掩码、原有前置/均匀日程和后 200 轮零奖规则。
- 使用独立随机流 850061，12 个物理类型各 100 worlds；不重复计算无实际意义的学习率标签。10 个选定平台 seed 全部保留。
- 10,000 次交叉 bootstrap 共享类型内 world 权重，动态方法另重抽训练 seed；固定基线不伪造训练重复。已独立验证三阶段 reshape 和恒定配对差保持。
- 每轮检查 `用户总效用+平台净收款=完成价值`；正式回放逐路径检查所有方法撤奖阶段与无奖励精确响应一致。
- `2.6/轮` 是最优全共享响应的期望净收款上界，不是每个随机匹配实现的硬上限。
